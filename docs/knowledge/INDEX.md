## Systems

The current contract of each system. Read before changing the system.

- [local-stack](systems/local-stack.md) — seven dev services in `deploy/compose.yaml` (Postgres, Redis, Redpanda, OTel collector, Jaeger, Prometheus, Grafana) on `127.0.0.1` ports from `LLMGW_*_PORT` with the CLAUDE.md defaults, project `llmgw` or `COMPOSE_PROJECT_NAME` from `deploy/.env` (FND-02); OTLP to Jaeger and Prometheus, Grafana datasource UIDs `prometheus` and `jaeger`; Grafana on 3301 with anonymous Admin answering only `Host: 127.0.0.1`; `tools/smoke/stack-check.sh` (12 checks) proves it, and `scripts/preflight.sh` warns about stack ports held by other processes; `test-support` singletons with the same images (`StackContractTest`), integrationTest-only (ARCH-11 and `checkTestSupportClasspath`).
- [mock-provider](systems/mock-provider.md) — deterministic OpenAI- and Anthropic-shaped fake on :8090 (FND-03): same request, same content and usage; provider-exact SSE flushed per event; per-model scenarios under `/__mock` (steps consumed exactly once); every non-admin request counted and journaled once, credentials kept only as an 8-hex SHA-256 fingerprint; runs as a process or a Testcontainers image (`integrationTest` suite); every wait is a Reactor timer, so BlockHound guards the code after it; reads of `/__mock/stats` and `/__mock/requests` wait up to `mock.journal.read-wait` for in-flight entries.
- [request-context-and-errors](systems/request-context-and-errors.md) — gateway-generated UUIDv7 `x-request-id` on every response, validated and echoed `x-client-request-id`, every error as the four-member OpenAI envelope from one `ErrorWebExceptionHandler` in `<app root>.error` (FND-04, ARCH-10); the envelope is always written before commit, a stackless stand-in aborts after commit, and neither logged throwables nor Reactor Netty's line carry the query string; `gateway-app`'s tests run under BlockHound and the seeded DRBG passes on the event loop.

## Patterns

- [singleton-test-containers-mirroring-compose-images](patterns/singleton-test-containers-mirroring-compose-images.md) — one Kotlin `object` per backing service holding a Testcontainers container started in a synchronized `lazy` and never stopped (Ryuk removes it); images in `StackImages`, kept equal to `deploy/compose.yaml` by a Docker-free test; isolation per test class is the consumer's; composition over a base class, and no Spring context can stop it.
- [raw-sse-frames-flushed-per-event](patterns/raw-sse-frames-flushed-per-event.md) — provider-exact SSE frames built as strings in pure code (`data: <json>\n\n`, `data: [DONE]\n\n`, `event: <type>\ndata: <json>\n\n`) and written through a `BodyInserter` calling `writeAndFlushWith`, one inner publisher per event; waits on a Reactor timer; errors after the first frame cannot change the status; never swallow `CancellationException`.
- [one-error-funnel](patterns/one-error-funnel.md) — every failure becomes a sealed `GatewayError`, one exhaustive core table gives status/type/code/message, one `WebExceptionHandler` in `<app root>.error` writes the OpenAI envelope; no `@ControllerAdvice` (ARCH-10). Revised after the FND-04 review: always write before commit, log a copy without Reactor's checkpoint, pin the handler bean set.
- [request-context-coroutine-element](patterns/request-context-coroutine-element.md) — the first `CoWebFilter` installs per-request values as a coroutine context element plus `MDCContext`, mirrored in an exchange attribute for the exception handler; core takes values as parameters.
- [architecture-rule-with-violating-fixture](patterns/architecture-rule-with-violating-fixture.md) — each Konsist rule is a function over a scope, applied to the real modules (must pass) and to an uncompiled fixture that breaks it (must fail), so no rule can go silently vacuous.

## Bugs

- [mock-journal-entry-visible-after-the-response](bugs/mock-journal-entry-visible-after-the-response.md) — the mock writes a journal entry after the response reaches the client, so an immediate read of `/__mock/stats` or `/__mock/requests` could miss it; found by the first Linux CI run; both now wait for `inFlight` 0, at most `mock.journal.read-wait` (medium, fixed).
- [compose-down-volumes-deny-rules-miss-spellings](bugs/compose-down-volumes-deny-rules-miss-spellings.md) — the `.claude/settings.json` patterns missed spellings with no argument before `down`, `docker-compose` and `docker volume rm -f`; fixed in the second-review fix commit.
- [gateway-body-limit-on-functional-route-gives-500](bugs/gateway-body-limit-on-functional-route-gives-500.md) — a functional handler's body read raises a bare `DataBufferLimitException`, which `ExceptionTranslator` maps to 500 with an ERROR trace, not 413; only the annotated-controller path is translated and tested; latent until GW-01 reads a body (low, open).
- [grafana-anonymous-admin-reachable-through-dns-rebinding](bugs/grafana-anonymous-admin-reachable-through-dns-rebinding.md) — the dev stack's Grafana (anonymous `Admin`, then on `127.0.0.1:3001`) served API writes for any `Host`, so a web page that rebinds its DNS name to `127.0.0.1` could add datasources (SQL on the dev Postgres with the documented credentials, SSRF from the container) from the developer's browser; fixed by `GF_SERVER_DOMAIN`, `GF_SERVER_ENFORCE_DOMAIN` and `GF_SERVER_ROOT_URL` on `127.0.0.1` (`deploy/compose.yaml:155-157`), proven by `stack-check.sh` check `grafana-host` (medium, fixed in FND-02 after review).
- [loggable-failure-logs-one-frame-after-reactor-checkpoint](bugs/loggable-failure-logs-one-frame-after-reactor-checkpoint.md) — `gateway-app`'s `LoggableFailure` copies the stack trace a Reactor checkpoint already cut to one frame and drops the checkpoint holding the rest, so every logged bug showed one frame; the test compared the copy with the truncated original; the copy now takes the frames from the checkpoint (medium, fixed in the FND-04 fix commit).
- [mock-serving-after-delay-runs-on-default-executor](bugs/mock-serving-after-delay-runs-on-default-executor.md) — after its first `delay` the mock runs on kotlinx's single `DefaultExecutor` thread (Spring starts handlers `Unconfined`), so BlockHound never saw that code and all timed continuations shared one thread; every wait is now `awaitDelay` on Reactor's `parallel` timer (medium, fixed in FND-03).
- [mock-scenario-times-expanded-into-memory](bugs/mock-scenario-times-expanded-into-memory.md) — `times` up to 2^31-1 is expanded into one object per request in `ScenarioStore`, so one `PUT /__mock/scenarios` gave `OutOfMemoryError`; steps are now unexpanded with cumulative ends, and `times` ≤ 1 000 000, steps ≤ 1000 (medium, fixed in FND-03).
- [mock-scenario-error-headers-not-validated](bugs/mock-scenario-error-headers-not-validated.md) — an invalid `error.headers` name was stored with 204 and then failed every request to that model with a 500 and an ERROR trace; names must be RFC 9110 tokens and values must pass Netty's own check (leading blanks and control characters rejected, an inner tab allowed), at `PUT` (low, fixed in FND-03, values in the second-review fix).
- [mapper-error-log-carries-raw-query-via-reactor-checkpoint](bugs/mapper-error-log-carries-raw-query-via-reactor-checkpoint.md) — every stack trace the mapper logged printed the raw query string through the checkpoint Spring's `ExceptionHandlingWebHandler` attaches as a suppressed exception; the mapper now logs `LoggableFailure.of(ex)`, which keeps the frames since the FND-04 fix commit (low, fixed in FND-04).
- [error-mapper-disconnect-check-turns-errors-into-empty-200](bugs/error-mapper-disconnect-check-turns-errors-into-empty-200.md) — the mapper skipped the write for anything `DisconnectedClientHelper` accepts, which matches phrases in any cause's message, so an error quoting "broken pipe" got 200 with an empty body; the envelope is now always written before commit, a 5xx is logged at ERROR unless its write failed with a client disconnect, and after commit a stackless stand-in aborts the connection (high, fixed in FND-04).
- [arch-10-misses-co-web-exception-handler-and-problem-details-handler](bugs/arch-10-misses-co-web-exception-handler-and-problem-details-handler.md) — a subclass of Spring 7's `CoWebExceptionHandler`, or Boot's `ProblemDetailsExceptionHandler`, named no listed type, so a second mapper passed ARCH-10; both and `ExceptionHandlingWebHandler` are now listed, with fixtures and a runtime bean-set guard (medium, fixed in FND-04).
- [committed-response-error-logged-twice-with-query-string](bugs/committed-response-error-logged-twice-with-query-string.md) — after commit `HttpWebHandlerAdapter` logged a second ERROR line with the raw query string and no request ID; that logger is now `off`, and after commit both mappers return a stackless stand-in, so Reactor Netty's line has no query either (low, fixed in FND-04 and the second-review fix).
- [architecture-test-inputs-miss-nested-module-sources](bugs/architecture-test-inputs-miss-nested-module-sources.md) — `*/src/**/*.kt` inputs missed nested modules, so `:architecture-tests:test` stayed UP-TO-DATE/FROM-CACHE and ARCH-8 did not run; inputs are now `**/*.kt` (medium, fixed in FND-01).
- [arch-6-misses-qualified-and-typealiased-wiring-annotations](bugs/arch-6-misses-qualified-and-typealiased-wiring-annotations.md) — `@org.springframework...Component` written inline, a star import or a typealias passed ARCH-6 outside app modules; the rule now resolves annotation text, star imports and typealiases (medium, fixed in FND-01).
- [arch-1-misses-jdk-clients-in-core](bugs/arch-1-misses-jdk-clients-in-core.md) — JDK HTTP/SQL clients are on every classpath, so inline `java.net.http...` or an `HttpURLConnection` import passed ARCH-1 in core; now `java.net`, `javax.net`, `java.nio.channels`, `com.sun.net.httpserver` and `jdk.net` are forbidden (URI allowlist), inline names are matched by one left-to-right scan of strings and comments, and `checkCoreClasspath` guards build scripts (medium, fixed in FND-01 and the second-review fix).

## Gotchas

- [kotlin-reflect-first-use-in-annotated-handlers-blocks-the-event-loop](gotchas/kotlin-reflect-first-use-in-annotated-handlers-blocks-the-event-loop.md) — Spring 7's first call of a Kotlin `@RestController` method runs kotlin-reflect on the event loop: a jar read of its built-ins and contended `ReentrantLock`s; `coRouter` does not; `EventLoopWarmup` resolves every Kotlin handler at startup.
- [mockk-spyk-of-a-jdk-object-needs-add-opens](gotchas/mockk-spyk-of-a-jdk-object-needs-add-opens.md) — MockK 1.14.11 runs on JDK 25, but `spyk` of a JDK object such as `Clock.fixed(...)` fails with `IllegalAccessException` unless `java.time` is opened; `mockk<Clock>()` and spies of our classes work.
- [testcontainers-tries-every-strategy-so-a-bad-docker-host-reaches-the-npipe](gotchas/testcontainers-tries-every-strategy-so-a-bad-docker-host-reaches-the-npipe.md) — on Windows a bad `DOCKER_HOST` or a strategy override still reaches the npipe, whose address is a constant; to prove "fails without a daemon", hide `os.name` from the test JVM with an init script.
- [webflux-committed-error-reaches-netty-log-or-completes-normally](gotchas/webflux-committed-error-reaches-netty-log-or-completes-normally.md) — after commit, `Mono.error(ex)` is logged by Reactor Netty 1.3.8's `HttpServerOperations` with the suppressed checkpoint and raw query, and an exception `DisconnectedClientHelper` accepts ends the response normally with 200; return a stackless exception of your own.
- [docker-desktop-publishes-ports-held-by-windows-processes](gotchas/docker-desktop-publishes-ports-held-by-windows-processes.md) — Docker Desktop on Windows publishes `127.0.0.1:<port>` although a Windows process already listens on it: `up` succeeds, healthchecks pass, and the host port still reaches that process; `scripts/preflight.sh` warns about held stack ports while the stack is down, and Grafana moved to 3301.
- [bash-xtrace-pollutes-captured-stderr](gotchas/bash-xtrace-pollutes-captured-stderr.md) — under `bash -x`, `out=$(f 2>&1)` captures the trace of the commands inside `f`, so comparisons fail falsely; debug with `BASH_XTRACEFD=7 bash -x ... 7>trace.log`.
- [grafana-serves-any-host-header-unless-enforce-domain](gotchas/grafana-serves-any-host-header-unless-enforce-domain.md) — Grafana 13.3.0 never checks `Host` unless `enforce_domain` is on, and skips its Origin-vs-Host CSRF check for requests without a login cookie, so anonymous auth answers DNS-rebinding requests; non-JSON cross-origin bodies get 400 and the preflight 404.
- [jaeger-2-22-legacy-search-api-404-breaks-grafana-health](gotchas/jaeger-2-22-legacy-search-api-404-breaks-grafana-health.md) — Jaeger 2.22.0 has no route for `/api/services` or `/api/traces?service=` (404) while `/api/traces/<id>` and `/api/v3/*` work (an empty v3 search is 404 too); Grafana 13.3.0's Jaeger datasource health therefore returns 400, and it cannot search Jaeger either (lookup by trace ID only; OBS-02 must not rely on Jaeger search through Grafana).
- [postgres-18-pg-isready-socket-ready-during-init-server](gotchas/postgres-18-pg-isready-socket-ready-during-init-server.md) — the postgres 18 entrypoint's temporary init server listens on the socket only, so socket `pg_isready` exits 0 before init is done; healthcheck with `-h 127.0.0.1`.
- [reactor-netty-rejects-control-chars-in-header-values-before-webflux](gotchas/reactor-netty-rejects-control-chars-in-header-values-before-webflux.md) — a control character (0x01, 0x7F) in any request header value gets Reactor Netty's empty `400` with `connection: close` before WebFlux runs, so no envelope and no `x-request-id`, plus one client-triggerable WARN from `HttpServerOperations` naming the header and path.
- [reactor-checkpoint-truncates-error-stack-to-first-frame](gotchas/reactor-checkpoint-truncates-error-stack-to-first-frame.md) — Reactor 3.8.8's checkpoint cuts the failing exception's own stack trace to its first frame and keeps the full trace in the suppressed `OnAssemblyException`; take the frames from it before dropping it.
- [spring-coroutine-handlers-resume-on-default-executor-after-delay](gotchas/spring-coroutine-handlers-resume-on-default-executor-after-delay.md) — Spring 7's `coRouter` handlers and `CoWebFilter`s run `Unconfined`, so after `delay` they continue on a thread BlockHound does not guard (`DefaultExecutor` in the running mock; the name varies by platform, so never pin it); wait with `Mono.delay` or on `Schedulers.parallel()`.
- [kotlinx-reactive-await-loads-context-injectors-on-first-use](gotchas/kotlinx-reactive-await-loads-context-injectors-on-first-use.md) — the first `await` on a `Publisher` runs `ReactiveFlowKt`'s static `ServiceLoader` jar read on the awaiting thread (an event loop in WebFlux); `Class.forName` it at startup.
- [reactor-netty-stop-waits-dispose-timeout-and-quiet-period](gotchas/reactor-netty-stop-waits-dispose-timeout-and-quiet-period.md) — with `server.shutdown=immediate` and an open connection, Boot 4.1.2 still stops in about 5 s (3 s `disposeNow`, 2 s quiet period); set `spring.reactor.netty.shutdown-quiet-period` and the lifecycle timeout, which is also the startup bind timeout.
- [blockhound-versions-carry-release-suffix](gotchas/blockhound-versions-carry-release-suffix.md) — BlockHound is published as `1.0.18.RELEASE`; `1.0.18` does not resolve.
- [detekt-default-test-excludes-miss-integration-test](gotchas/detekt-default-test-excludes-miss-integration-test.md) — detekt 2.0.0-alpha.6's default test excludes have no `**/integrationTest/**`; nine active rules need the override.
- [kover-excludes-only-the-test-compilation-by-default](gotchas/kover-excludes-only-the-test-compilation-by-default.md) — Kover 0.9.11 reports every JVM compilation except `test` as application code; add `integrationTest` to `excludedSourceSets` and leave `includedSourceSets` empty.
- [gradle-configuration-cache-rejects-script-object-in-lambda](gotchas/gradle-configuration-cache-rejects-script-object-in-lambda.md) — a task lambda reading a top-level `val` of a `.gradle.kts` captures the script object, which the configuration cache cannot serialize; capture a local copy.
- [spring-exception-handling-web-handler-checkpoint-carries-raw-query](gotchas/spring-exception-handling-web-handler-checkpoint-carries-raw-query.md) — Spring 7.0.10's `ExceptionHandlingWebHandler` adds a Reactor checkpoint `HTTP <method> "<path>?<raw query>"` to every error as a suppressed exception that cannot be removed; log a copy without it (`LoggableFailure`).
- [spring-disconnected-client-helper-matches-phrases-in-cause-chain](gotchas/spring-disconnected-client-helper-matches-phrases-in-cause-chain.md) — Spring 7.0.10's `DisconnectedClientHelper` returns true when any cause's message contains "broken pipe" or "connection reset by peer"; use it only to classify a write that failed, never to skip a write or to pick the level for the original exception.
- [jdk-drbg-seeds-lazily-on-first-nextbytes](gotchas/jdk-drbg-seeds-lazily-on-first-nextbytes.md) — `SecureRandom.getInstance("DRBG")` reads entropy on the first `nextBytes`, not in `getInstance`. Every draw takes the instance lock. The reseed when the counter overflows, after about 2^31 draws, reads only from memory. Under BlockHound the first draw trips on Linux and not on Windows; after a startup draw nothing trips on either.
- [spring-httpstatus-deprecated-aliases-never-resolved](gotchas/spring-httpstatus-deprecated-aliases-never-resolved.md) — `HttpStatus.resolve(413)` is `CONTENT_TOO_LARGE` and `resolve(422)` is `UNPROCESSABLE_CONTENT`, so `==` on the deprecated `PAYLOAD_TOO_LARGE` or `UNPROCESSABLE_ENTITY` never matches; compare integers.
- [detekt-forbiddenvoid-flags-mono-void](gotchas/detekt-forbiddenvoid-flags-mono-void.md) — `ForbiddenVoid` is active by default with `ignoreUsageInGenerics: false`, so every `Mono<Void>` is a finding; set `ignoreUsageInGenerics: true`.
- [konsist-annotation-fqn-unresolved-for-qualified-star-typealias](gotchas/konsist-annotation-fqn-unresolved-for-qualified-star-typealias.md) — Konsist resolves an annotation's `fullyQualifiedName` only through an explicit import; inline-qualified, star-imported and typealiased annotations come back unresolved.
- [konsist-paths-and-module-names-use-platform-separator](gotchas/konsist-paths-and-module-names-use-platform-separator.md) — `projectPath` and nested `moduleName` use `\` on Windows and `/` on Linux; `ModuleFile` normalizes both, so compare through it.
- [konsist-wildcard-import-name-omits-star](gotchas/konsist-wildcard-import-name-omits-star.md) — a star import's `name` has no `.*` (`isWildcard` is true); match prefixes on a segment boundary.
- [konsist-does-not-scan-kts-files](gotchas/konsist-does-not-scan-kts-files.md) — Konsist scopes hold `.kt` only; no rule sees a dependency added in a build script, so `checkCoreClasspath` guards core's resolved classpath.
- [detekt-2-check-runs-plain-detekt-task](gotchas/detekt-2-check-runs-plain-detekt-task.md) — detekt 2.0.0-alpha.6 makes `check` depend on the untyped `detekt` task; swap in `detektMain`/`detektTest`.
- [ktlint-gradle-lints-kotlin-dsl-generated-sources](gotchas/ktlint-gradle-lints-kotlin-dsl-generated-sources.md) — kotlin-dsl generated sources are in `main`; exclude them by absolute `Path.startsWith`, computed outside the lambda for the configuration cache.
- [gradle-version-catalog-alias-prefix-needs-asprovider](gotchas/gradle-version-catalog-alias-prefix-needs-asprovider.md) — `ktlint` beside `ktlint-gradle` makes `libs.versions.ktlint` a group; use `.asProvider()`.
